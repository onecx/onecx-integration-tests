= Reference: CLI, Environment Variables, and Run Artifacts

This page is a quick-lookup reference for all runtime controls and outputs. It covers available CLI flags, environment variable overrides, the run artifact directory structure, and common troubleshooting steps. For conceptual context behind each option, refer to the relevant chapter pages.

== Platform Configuration

Configuration source of truth:

* `platform.json` validated by `integration-tests.schema.json`
* Expected top-level key: `platformConfig`
* Default path: `integration-tests/platform/platform.json`

Important fields:

* `importData`
* `withLoggingEnabled`
* `heartbeat`
* `platformOverrides`
* `container`

See xref:contract.adoc[Contract and Configuration] for full field details.

== Explicit Contract Selection

Select the contract explicitly with `--config <path>`:

[source,bash]
----
onecx-it-runner --config integration/platform.json
----

* The path is resolved strictly: the runner checks the path as given, then against the current working directory. If it does not exist, the run fails with `Configuration file not found: <path>`.
* There is no fallback to the default path or recursive discovery when a path is provided.
* Discovery (default path, then recursive search) applies only when no `--config` is given.

Use `--config` in CI so the run pins the exact contract. Discovery without it is a local convenience only.

== CLI Options

The runner is invoked the same way in this repository and by a consumer; the only difference is how the entry resolves.

In this repository the entry is wrapped as `npm run it:run`. A consumer uses the published CLI entry `onecx-it-runner` (the `bin` of the installed package), which resolves inside the installed layout without manual `node_modules` paths.

Runner entry command:

In this repository:

[source,bash]
----
npm run it:run -- [options]
----

As a consumer:

[source,bash]
----
onecx-it-runner [options]
----

The entry is a working, self-resolving `bin`: a single install of `@onecx/integration-tests` is sufficient, and consumers declare no `testcontainers`, `dockerode`, or `axios` package.

[.stripes-even,cols="25,20,55"]
|===
| Option | Default | Description

| `-v, --verbose`
| `false`
| Enable verbose output

| `--capture-logs`
| `true`
| Capture runner console output and container streams to artifact logs

| `--dry-run`
| `false`
| Validate setup and print execution plan without starting containers

| `--config <path>`
| `undefined`
| Path to the platform.json contract. Strict: fails with `Configuration file not found: <path>` when it does not exist, with no fallback.

| `-h, --help`
| `false`
| Show help text
|===

Example:

In this repository:

[source,bash]
----
npm run it:run -- --verbose --capture-logs
----

As a consumer:

[source,bash]
----
onecx-it-runner --verbose --capture-logs
----

== Consumer dry-run check

The dry-run flag is the consumer-side verification step: it resolves and validates `platform.json`, determines the run mode, and exits without starting containers. A successful dry run exits with status `success`.

Configuration must resolve before the dry-run branch is reached. If no valid `platform.json` is found, the runner exits with status `failure` and never reaches the dry-run step — so run the check from a working directory where a valid configuration resolves (the caller repository root, or this repository).

In this repository:

[source,bash]
----
npm run it:run -- --dry-run
----

As a consumer:

[source,bash]
----
onecx-it-runner --dry-run
----

Run the dry run immediately after installing the runner to confirm the entry resolves and the dependency closure is complete before starting any real run.

== Environment Variables

[.stripes-even,cols="30,70"]
|===
| Variable | Description

| `IT_VERBOSE`
| Default value source for `--verbose`

| `IT_CAPTURE_LOGS`
| Default value source for `--capture-logs`

| `RUN_ID`
| Optional run identifier override used for artifact path resolution

| `E2E_RUN_ID`
| Backward-compatible run identifier fallback

| `E2E_BASE_DIR`
| Base directory for E2E output path resolution

| `ARTIFACTS_ROOT`
| Runtime artifact root set by run context
|===

== Run Artifacts

Artifacts are written under:

`integration-tests/artifacts/<run-id>/`

Typical structure:

[source,text]
----
integration-tests/artifacts/<run-id>/
	summary.json
	logs/
		runner-output.log
		containers.log
	reports/
	e2e/
		platform-info.json
		e2e-executions.json
	e2e-results/
----

`summary.json` fields include:

* `runId`
* `startTime`
* `endTime`
* `durationMs`
* `exitCode`
* `status`
* `mode`
* `e2eExecutions`
* `e2eAggregate`
* `interruptedBy` when the runner stopped after `SIGINT` or `SIGTERM`
* `configPath` the path passed via `--config`, or an empty string when discovery was used
* `runnerVersion` the version of the published runner package that performed the run
* `resolvedImages` a map of logical image name to the final image it resolved to

The `e2eExecutions` and `e2eAggregate` fields replace the former singular E2E result shape. Consumers that read `summary.json` must use the new fields.

The provenance fields (`configPath`, `runnerVersion`, `resolvedImages`) make each run auditable: a successful run records the exact contract, runner version, and the image each logical service resolved to.

== Troubleshooting Quick Checks

Use this order for fast diagnosis:

* Confirm config validation succeeds in `--dry-run`
* Confirm E2E section exists in `platformConfig.container.e2e`
* Confirm health checks pass before E2E execution
* Review `summary.json` for final status and exit code
* Review `logs/containers.log` for container startup and dependency issues
